Proposed architecture and implementation boundaries

Control API: owns runs, phase states, scoped approvals and an append-only event history. An authenticated host runner accepts allowlisted commands and reports structured events. The browser never receives SSH credentials or executes shell strings.

Existing tools: adapt agent-fleet for session lifecycle and phased-delivery for phase orchestration. Their current skills describe CLI operations and file-based reports, not this proposed API contract. Reliable phase events and command acknowledgements would need implementation.

Safety: one command owner per run, idempotent command IDs, approvals bound to an exact phase revision, heartbeat freshness and explicit unknown/error states. Host reconnect must reconcile state before retrying an action. Human approval cannot substitute for passing tests and independent review.

Persistence: the future backend stores operational state; Outline stores decisions and handoffs. This mockup stores nothing and calls no APIs. Pause means stop scheduling new work, not interrupt a command already running.
